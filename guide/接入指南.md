# 接入指南

**读者**：另一个 DSH 客户端插件的作者（人或 AI）。你在写自己的插件，想用 GUIFrame 的入口坞 / 面板骨架 / 浮层 / 外观变量。
**不读这个**：你要改 GUIFrame 本包 —— 那是另一回事（包根 `README.md` 的「维护者附录」一节）。
**适用范围（先说清）**：这是 **`dsh-gui-frame` 1.0.0** 的接入说明 —— 本版只有 `dock` / `panel` / `overlay` / `theme` 四项能力；数据通道、布局编辑与持久化、浮动窗口、测试工作台、演示面板**本版一个都没有**（清单见 `README.md`「本版没有的东西」）。准则：**本文档提到的成员，本版都真的存在**。

---

## §1 你接入的是什么

GUIFrame 以 **Cordis 客户端服务** 的形态存在：服务名 `gui-frame`，在代码里写作 **`ctx.guiFrame`**。

它**不做**挂载接口 —— 平台已有座位（slot）注册表、61 个座位与 9 键种子表。它做的是「入口规则 + 面板骨架 + 业务级复合组件 + 架构级浮层」。你**不需要**改自己的构建链、不需要 npm 依赖本包、不需要 `dsh.client.external`：

- 组件通过**服务**拿（`ctx.guiFrame.components`），不通过模块 import；
- 你自己的 React 与平台种子照旧（`react` / `react/jsx-runtime` / primitives 等）。

一句话：**你不是在依赖一个库，你是在消费一个服务。**

## §2 第一步：探测（这一步做错，整页起不来）

本包**可能没装**、也可能装了但**没激活**（依赖缺失时它自己让位 —— 设计如此）。你的插件在两种情况下都必须照常跑。

### ✅ 唯一推荐写法：`ctx.get`

```js
function apply(ctx) {
  const gui = ctx.get('gui-frame');
  if (!gui) return;                  // 本包不在场 ⇒ 你自己那套照旧（或不渲染这一块）
  // …用 gui.register / gui.overlay / …
}
```

### ❌ 不要写 `inject: ['gui-frame']`

客户端插件声明 `export const inject = ['gui-frame']` 而本包不在场时，你的 fiber 会**永久 pending**；外壳的 boot kernel 一旦发现有 entry 不是 active，就会 `throw` ⇒ **整个页面进入启动失败态**，不是「少一块功能」。

> 这不是风格偏好，是平台机制：boot 阶段**没有插件级失败隔离**，失败判定是全局的。

**结论**：把 GUIFrame 当**可选增强**，用 `ctx.get` 探测。本包自己也守同一条规矩（它提供前先 `ctx.get` 探测、发现重名就记诊断并主动让位）。

## §3 第二步：登记入口

```js
const dispose = gui.register(entry, Component);
```

### 两种 `kind`（决定你的入口去哪）

| `kind` | 去哪 | 你得到什么 |
| --- | --- | --- |
| `'action'` | **进「按钮面板」**：用户在侧栏点 GUIFrame 那一行，浮出的面板里就有你这一条 | 面板里**原样渲染你的组件**；可带角标 |
| `'panel'`（缺省） | **不进坞**：本包把你成对注册进平台 `sidebar.panellist` + `main` | 侧栏出现属于你的一行，主区出现你的一页 |

> 「按钮面板」是**动作型入口的收纳台**，不是入口目录（原始需求就是「侧栏按钮太多、还可能被别的插件挡住」）。面板类页面请用 `'panel'`，别塞进坞。

### `entry` 字段表

| 字段 | 必填 | 形态 | 说明 |
| --- | --- | --- | --- |
| `id` | ✅ | 字符串 | **必须带包名前缀**（如 `'你的包名/开关'`）；只允许 `[A-Za-z0-9._-/]`；≤ 128 字符；**不得用保留 key `conversation`** |
| `label` | | 字符串 \| thunk | 显示名。传 **thunk**（`() => t('…')`）可跟随语言/每次读取重新求值 |
| `order` | | 整数 | 排序键；缺省排在最后（`order` 相等时按注册先后） |
| `group` | | 非空字符串 | 分组名 |
| `kind` | | `'panel'` \| `'action'` | 缺省 `'panel'` |
| `source` | | 非空字符串 | **你自报的包名**（本包用它做 stale 判定） |
| `icon` | | React 组件 | 传给坞**自绘字形**的地方（侧栏那一行等）。**不是图标名字符串**。⚠ 动作型入口在按钮面板里的那一行**不画图标槽** —— 见 §7 坑 ① |
| `badge` | | 任意 | 角标值，由坞自绘 |

`Component` **必填**：函数组件 / 类组件 / `memo` / `forwardRef` 形状都可。**本包不碰你的组件内部结构**（这是明写的边界：内容层归你）。

### 返回值：一个 disposer

```js
dispose();   // 幂等；卸载你的 fiber 时 Cordis 会自动跑它
```

### 你在组件里能拿到什么 props

面板行渲染你的组件时，本包注入四个 props：

| prop | 类型 | 含义 |
| --- | --- | --- |
| `id` | 字符串 | 你在 `register` 里登记的 `id` |
| `label` | 字符串 \| null | 求值后的当前标签 |
| `setBadge(v)` | 函数 | 改角标（角标由坞自绘） |
| `setLabel(v)` | 函数 | 改标签值 |

> ⚠ **两条边界（不许含糊）**：① 面板行里的**文字与图标由你自己的组件渲染**，本包只提供外壳与角标 —— 你想变文字，直接 `setState` 就行，不必依赖 `setLabel`；
> ② **侧栏那一行的可见文字由平台渲染**（本包交上去的是 label thunk）—— **不要承诺「侧栏文字会实时变」**，平台何时重读属平台行为。

## §4 第三步：用能力（本版四项，逐项签名见 `契约速查.md`）

```js
// ① 入口坞：动作型入口进「按钮面板」（登记写法见 §3）
gui.dock.open();      // ⇒ boolean（此刻是否在场）
gui.dock.isOpen();
gui.dock.close();

// ② 面板骨架：拿本包用官方 primitives 实现的复合组件
const Panel = gui.components.get('Panel');            // 拿不到 ⇒ undefined（别当成空组件）

// ③ 浮层：开一扇「你自己的」浮层（family 缺省 'floating'，另有 toast 族）
const handle = gui.overlay.open({ id: '你的包名/面板', family: 'floating', component: MyPanel, props: {} });
handle.close();

// ④ 外观：不调 API，定义公开变量（§10）
// :root{ --guif-panel-radius: 10px; }
```

> **本版只有这四项**：没有数据通道（`channel`）、没有布局编辑与持久化（`layout`）、没有可拖可缩的浮动窗口（`window` / `FloatingWindow`）、没有测试工作台（`workbench`）与演示面板 —— 本版的服务面成员与命名空间里根本没有它们。
> ⚠ `supports(name)` 只认 `dock` / `overlay` / `panel` 三项；`theme` 是外观切片、不在能力名单里 ⇒ **`supports('theme')` 恒 `false`**（已知口径缺口，不是你写错了）。

**六个冻结复合组件**：`Panel` / `Toolbar` / `Empty` / `ErrorState` / `List` / `KeyValue`。它们**必须接受的 props** 可以用 `gui.components.props('Panel')` 在运行期问出来（返回名字数组；不是冻结名则返回 `null`）。原子组件（Button / Tooltip / Modal / Tag…）**不由本包转发** —— 你从平台 primitives 种子自己取。

## §5 能力缺席时怎么办（降级）

先问，再调：

```js
if (gui.supports('overlay')) { … }        // 声明里有它 且 对应实现已装配
```

`supports(name)` 对三个能力名都有效：`dock` / `overlay` / `panel`。

**失败语义分三档（照这个写你的错误处理）**：

| 档 | 谁 | 表现 |
| --- | --- | --- |
| **返回 `false`，不抛** | `dock.open/close/isOpen` | 能力不在场是**正常一态**，不是异常 —— 你不需要为「弹不出来」写 try/catch |
| **抛错** | `overlay.open(...)`（抛 `GUIF-E-CAPABILITY-ABSENT`）、`register(...)`（形态错） | 调用方写错或装配缺失 —— **绝不静默 no-op** |
| **幂等 `false`** | `overlay.close(id)` / `overlay.bringToFront(id)` 传了合法但不存在的 id | 形态非法才抛（`GUIF-E-OVERLAY-ID`） |

错误判型用 `err.code`（`GUIF-E-*` / `GUIF-W-*`），**不要** match 错误文案、也不要用 `instanceof Error`（跨 bundle 实例会失配）。全部码表见 `契约速查.md`。

## §6 生命周期：三条纪律

1. **不要解构服务**。`const { register } = ctx.guiFrame` ⇒ 丢掉「调用点绑定」，清理会挂到错误的 fiber 上。正确写法恒为 `ctx.guiFrame.register(...)`。
2. **不要缓存命名空间对象跨 ctx 用**。`ctx.guiFrame.overlay` 每次访问读的是**调用方 ctx**；把它存进模块级变量再给别的 ctx 用，等于把副作用挂错地方。
3. **本包卸载后重挂载会重新 apply 你的插件**。所以你的 `apply` 必须**幂等**（不要假设「全局只跑一次」）。

本包给 `register` / `components.register` 返回的 disposer 都是**幂等**的，你可以在清理里放心再调一次。

## §7 已知坑（都是实测踩过的）

① **一个按钮＝图标＋文字，都由你的控件画**。坞**不**在动作型行里画图标槽 —— 因为「接口给了两处图标来源、契约却没定谁负责」时，行里会出现**两个图标**。所以：你在面板里长什么样，完全由你的 `Component` 决定。
② **你的控件静止态的内联样式不会被中和**。坞的样式表压不过你写在元素上的 `style="background:…"`（类名写法会被中和）。
③ **但 `:hover` / `:active` / `:focus` / `:focus-visible` 四态的背景会被强制透明**（`!important`）—— 与 DSH 侧栏「整行一个悬停面」一致。你**有意**画的悬停底色也会被抹掉（这是拍板过的口径）。**想改整行的悬停色**：见 §10（定义 `--guif-dock-row-bg-hover`，不用跟这条规则打架）。
④ **`id` 撞车会抛** `GUIF-E-ENTRY-DUPLICATE`：同一 id 不能注册两次（先调上一次的 disposer）。
⑤ **`kind` 决定入口去哪**，写错等于放错位置；`kind` 非法值抛 `GUIF-E-ENTRY-INVALID`。
⑥ **`overlay.open` 的 `spec` 形态由本包校验**：`spec` 不是普通对象、`family` 不在层级族里 ⇒ 抛 `GUIF-E-OVERLAY-SPEC`（见 `契约速查.md` §5 的族名全集）。
⑦ **`dock.open()` 开的是「共享 UI」，不是你的私有窗口**。它归本包整体所有：`open()` 之后**你卸载不会替你关掉它**。要成对收尾就自己 `close()`。（`overlay.open` 才是调用方私有窗口 —— 两者故意不同。）
⑧ **浮层层号用数字，但只有本包一张表**。你**不要**自己写 `z-index`；传 `options.z` 会被校验（极值抛 `GUIF-E-Z-RANGE`、越段只告警 `GUIF-W-Z-SEGMENT`），缺省由本包从 100 起单调分配。`data-guif-z` 属性上能看到实际层号。
⑨ **`icon` 传组件，不是名字**（传字符串不会报错，但那一行不会有图标）。
⑩ **`ctx.guiFrame` 的成员是「原型方法 / 原型取值器」**：这是为了让清理落在**调用方** fiber 上。别指望能自由地把它包一层再转发（包装函数会把调用点绑定的 ctx 吃掉）。

## §8 已知盲区（本包也兜不住的）

本包有一条「客户端失败 → 宿主终端」的诊断链路，但**有两类失败它注定看不到**：

1. **boot 阶段就崩的页面**：本包自己都没加载起来，自然发不出上报 —— 那类失败只能看浏览器控制台 / 启动失败页。
2. **被别人的 pending / 别人的 apply 抛错拖死的场景**：那时本包没有代码在跑。前者是你（或别人）写了 `inject` 导致 fiber 挂起，后者是任何插件的未捕获异常 —— 都属全局失败，不是本包能隔离的。

## §9 自检手段（你不必读本包源码）

运行期就能问清楚：

```js
gui.version                        // 服务面版本（字符串；本版 1.0.0）
gui.capabilities                   // 能力名数组（本版 3 项：dock / overlay / panel）
gui.supports('overlay')            // 某一项此刻可用吗
gui.components.names()             // 复合组件名（冻结名 ∪ 已登记）
gui.components.props('Panel')      // 某个组件必须接受的 props 名
```

想到手边有**确切签名**：`契约速查.md`（那几张名单与本包的契约表是机检对锁的，改一处必红）。
想看**活样本**：本包自带一个**坞管理页**（自检页 —— 「本包注册且非 `action` 的入口」都列在那里，点一行就切到它那一格）。⚠ 两条如实说明：① 本版**没有演示面板**（demo 四段）；② 这一页挂在主区 key `dsh-gui-frame/workbench`，而**本版没有工作台开关去选它** —— 浮层能力缺席时「折回页」会退化成直接渲染管理页；浮层在场时正常路径不经过管理页（要直选得自己调平台 `layout.selectPanel('dsh-gui-frame/workbench')`）。

## §10 改外观：定义变量，不用跟选择器打架

**「按钮面板里那些按钮的底色（含悬停）能改吗？」—— 能，而且不用写 `!important` 去盖本包的规则。**
全套名字只有 16 个，见 `契约速查.md` §7（那张表与本包实现机检对锁）。这里只说怎么用。

### 三种粒度（从粗到细）

```css
/* ① 全局：整个页面都用你的口径 */
:root{ --guif-dock-row-bg-hover: rgba(38,49,72,.14); }

/* ② 只改「按钮面板」这一块：在行的任意祖先上定义即可 */
[data-guif-panel-frame]{ --guif-dock-row-bg-active: rgba(38,49,72,.10); }   /* 浮出的面板外壳锚点 */
[data-guif-dock-actions]{ --guif-dock-row-fg: rgb(0,120,255); }            /* 面板里的按钮列表容器 */

/* ③ 只改某一个按钮：行锚点**带值**，值就是你 register 的那个 id */
[data-guif-dock-action="你的包名/开关"]:hover{ --guif-dock-row-bg-hover: rgba(214,88,88,.18); }
```

`var()` 是**继承**来的：你在祖先上写下 `--guif-dock-row-bg-hover`，本包那一行里的
`background: var(--guif-dock-row-bg-hover, …)` 就直接取到你的值 —— **没有特异性之争，也不需要 `!important`**。

### 悬停/激活那两态怎么写

悬停底色、激活底色、焦点环、激活字色属**伪类层**，本包写在样式表里。你想按状态给不同值，
就在**同一个状态**上定义变量（下面的写法与上面的机制同源，依然不用 `!important`）：

```css
[data-guif-dock-action]:hover{ --guif-dock-row-bg-hover: rgba(38,49,72,.14); }
[data-guif-dock-action]:focus-visible{ --guif-dock-row-focus-ring: var(--dsw-alias-brand-primary); }
```

### 四条边界（都不是借口，是机制）

① **只取用、不声明**：变量要写在 `var(名字, 缺省)` 的**取值位**，别写成元素上的内联自定义属性
（`style="--guif-dock-row-bg-hover: …"`）。自定义属性走继承，**元素自己声明一次，祖先给的覆盖值就被它挡死**
—— 本包自己踩过这个坑（见 `panel/components.mjs` 里那段注释）。
② **你控件写在元素上的内联样式不会被中和，但四态底色会被强制透明**（§7 坑②③）：行内按钮自己画的
悬停底色仍会被抹掉 —— 所以**悬停色请画在整行上**（`--guif-dock-row-bg-hover`），这也是本包的口径
「整行一个悬停面」。
③ **管不到侧栏那一行**：侧栏的坞入口由**平台**渲染（本包只交 label 与图标），这一族变量管的是
**面板里的按钮行**与面板本身。想改侧栏那一颗，得动平台侧，不在本包接口内。
④ **行圆角与行间距是「美学秩序」里的不变量**（用户原话：「**改行圆角和行间距会影响面板的美学秩序，
所以不要。**」）：`border-radius: 8px` 与行之间的 `4px` 间距**固定**（与 DSH 侧栏 `.panelRow` / `.panelList`
逐值同源）—— **不是漏开，是不开**。这一族只给「按主题、按插件真的会有区别」的东西（颜色与状态）；
几何/节奏属设计不变量。需要别的值 ⇒ 提需求改设计，别指望定义变量。

### 想自己验一下

面板里的列表容器带着 `data-guif-dock-actions="<行数>"`、每一行带着 `data-guif-dock-action="<入口 id>"`、
面板外壳带着 `data-guif-panel-frame`、样式表带着 `data-guif-theme="gui-frame-dock-panel"`
—— 真机断言用这几个锚点就够，不必猜选择器。
