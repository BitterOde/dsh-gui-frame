# 契约速查

**这是一份「随查」文档**：每张表的第一列是**成员名**，它们与本包的契约真源**机检对锁**（`tests/contracts/guide-contract.test.mjs` 双向比对：文档漏一个 / 多一个都判红）。所以这张表不会悄悄过期。

**真源**（你可以按路径核对，虽然它们不随包发布）：
`src/client/contracts/service-face.mjs`（成员与能力）、`components.mjs`（复合组件与 props）、`errors.mjs`（错误码）、`layers.mjs`（数字层级表）、**`src/client/kit/tokens.mjs`（公开外观变量，见 §7）**。

服务名恒为 **`gui-frame`**，代码里写作 **`ctx.guiFrame`**；服务面版本 `1.0.0`。

**形态为什么是契约**：`register/supports` 必须是**原型方法**、三个命名空间必须是**原型取值器** —— Cordis 服务代理在**调用点**把 `this.ctx` 绑到调用方 ctx，清理才会落到你的 fiber 上。⇒ **不要解构**（`const { register } = ctx.guiFrame` 会静默破坏这一点）。

**`supports(name)`**：能力名 ∈ `dock` / `overlay` / `panel`；返回「声明里有它**且**对应实现已装配」。三个能力都要对应切片装配后才为 `true`（`panel` 与 `dock` 同切片：面板骨架挂在坞的成对注册上）。

## 2. 三个命名空间（3 个）

### 2.1 `ctx.guiFrame.components`

<!-- members:namespace:components -->
| 成员 | 签名 | 语义 |
| --- | --- | --- |
| `register` | `register(name, Component) ⇒ disposer` | 贡献一个可复用组件（重名抛 `GUIF-E-COMPONENT-DUPLICATE`） |
| `has` | `has(name) ⇒ boolean` | 冻结清单里的名字恒为 `true` |
| `get` | `get(name) ⇒ Component \| undefined` | 取实现；**未装上时返回 `undefined`**，别当成空组件 |
| `names` | `names() ⇒ string[]` | 全部可用名字（冻结名 ∪ 已登记），已排序 |
| `props` | `props(name) ⇒ string[] \| null` | 该组件**必须接受的 props 名**；不是冻结名 ⇒ `null` |
<!-- /members:namespace:components -->

### 2.2 `ctx.guiFrame.dock`

<!-- members:namespace:dock -->
| 成员 | 签名 | 语义 |
| --- | --- | --- |
| `open` | `open(options?) ⇒ boolean` | 打开（已在场则重新置顶）「按钮面板」；`options.anchor` 可选定位矩形 |
| `close` | `close() ⇒ boolean` | 关掉（幂等）；返回**操作前**是否在场 |
| `isOpen` | `isOpen() ⇒ boolean` | 面板此刻是否在场 |
<!-- /members:namespace:dock -->

三条语义（改它就是改公开契约）：① 与「点侧栏那一行」是**同一扇**面板；② **共享 UI**，不把副作用挂到你的 fiber 上（你卸载不会替你关）；③ 能力缺席 ⇒ **返回 `false`，不抛**。

### 2.3 `ctx.guiFrame.overlay`

<!-- members:namespace:overlay -->
| 成员 | 签名 | 语义 |
| --- | --- | --- |
| `open` | `open(spec, options?) ⇒ { id, z, close(), bringToFront() }` | 开一扇**你自己的**窗口 |
| `close` | `close(id) ⇒ boolean` | 关闭；合法但不存在的 id ⇒ `false`（幂等），形态非法抛 `GUIF-E-OVERLAY-ID` |
| `bringToFront` | `bringToFront(id) ⇒ boolean` | 点击置顶（同层内叠放序） |
<!-- /members:namespace:overlay -->

`spec`：`{ id?, family?, title?, component?, props? }`（`family` 缺省 `'floating'`）；`options`：`{ z? }`（显式层号）。

`err.code` 是**唯一**判型依据（不要 match 文案，也不要用 `instanceof Error`：跨 bundle 实例会失配）。`GUIF-E-*` 抛出，`GUIF-W-*` 只记诊断不阻断。

> **本表是错误码族的全集，不是「本版还活着的码」子集**：码表与公开面一起冻结，退役一个码要单独走一次显式变更。
> ★ **v1.0 裁掉了 `channel`（数据通道）与 `layout`（布局编辑与持久化）两条能力线**，但这两个族的码**仍留在冻结集合里**（`GUIF-E-CHANNEL-INVALID` / `GUIF-E-LAYOUT-INVALID` / `GUIF-W-LAYOUT-CORRUPT`）——
> 本版**不会**由本包抛出它们；写判型分支时照全集写即可（它们的存在不代表接口存在）。

## 5. 数字层级表（5 个族）

**层级用数字表述**（这是定过的口径），但**只有本包一张表**。你不写 `z-index`：

| 号段 | 族 | 给谁 |
| --- | --- | --- |
| ≤ 40 | （非托管·在下带） | 你要落在托管浮层**之下** |
| 41 – 49 | — | 缝：既不在下带也不在托管段 ⇒ 调用时只告警 |
| 50 – 199 | `floating` | **缺省族**：不传 `z` 时从 100 起单调自增。⚠ v1.0 **不随包提供**可拖可缩的浮动窗组件（`window` / `FloatingWindow`）；族名与号段照旧保留 |
| 200 – 299 | `panel` | 面板（贴边浮出：**无拖动条、无缩放手柄**）—— 本版的「按钮面板」与浮出面板走这一族 |
| 300 – 499 | `dialog` | 对话框 |
| 500 – 699 | `popover` | 气泡 |
| 700 – 999 | `toast` | 轻提示 |
| ≥ 1000 | （非托管·盖住带） | 你要**盖住**托管浮层 |

族名全集（`LAYER_FAMILIES`）：`floating` / `panel` / `dialog` / `popover` / `toast`。
⚠ 族名全集是**层级表的声明**（5 个），不等于「本版都提供对应组件」：本版实际交付的浮层形态是**浮出面板（`panel`）**、**`floating` 缺省族的自有浮层**与 **toast**；`dialog` / `popover` 的原子容器**依赖平台 primitives**，本包只在拿得到时转发。**可拖可缩的浮动窗组件不在本版**。
**极值拒绝、越段告警**：非整数 / 非有限数 / 超出 `[-2147483648, 2147483647]` ⇒ 抛 `GUIF-E-Z-RANGE`；落错段 ⇒ 只记 `GUIF-W-Z-SEGMENT`。
实际层号挂在窗口根节点的 **`data-guif-z`** 属性上，便于你的真机断言。

| `--guif-toolbar-gap` | `6px` | 骨架工具条里按钮的间距 |
<!-- /members:vars -->

两条**机制**（违反任一条，这个接口就是假的）：
① **只取用、不声明** —— 这些名字只出现在 `var(名字, 缺省)` 的**取值位**；本包不会、你也不该把它写成元素上的
内联自定义属性（`style={{'--guif-…': …}}`）：自定义属性走继承，**元素自己声明一次，祖先给的覆盖值就被它挡死**。
② **缺省即现状** —— 没人覆盖时观感与出厂逐字一致（冻结在 `tests/unit/dock-style-vars.test.mjs`）。

⚠ **美学秩序里的不变量（不是可变项，也不是「漏开」）**：**行圆角**（固定 `8px`）与**行与行的间距**（固定 `4px`）
—— 它们与 DSH 侧栏 `.panelRow` / `.panelList` **逐值同源**，是这个面板「看着像同一个面板」的基础。用户
的原话：「**改行圆角和行间距会影响面板的美学秩序，所以不要。**」⇒ 想要别的值就得改本包实现（或提需求改设计），
**不是配置项**。可调面只给「按主题、按插件真的会有区别」的东西：**颜色与状态**。
写法与逐按钮定位见 `接入指南.md` §10。

## 9. 内部面（`__` 前缀 —— 不要用）

`ctx.guiFrame.__install` / `__slice` / `__slices` / `__entries` / `__note` 是**装配契约 v1** 的内部面（本包自己的能力模块用它装配），**不在公开面快照里**，随时可能改。接入方只用本文件列出的成员。

宿主半区同理：本包在宿主侧注册的路由（含 `/api/gui-frame/diagnostics`）是**它自己的**诊断链路，不是给别的插件调用的 API。
