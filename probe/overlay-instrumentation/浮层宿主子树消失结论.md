## 3. 差分归属：真 pointerdown ⇒ 设计内的点外关闭

- 事件账（document 捕获期）：`t=8553.1 pointerdown → button[data-guif-demo-open="window"]`；**`t=9500.9 pointerdown → button[data-guif-demo-open="dialog"]`**（x=432,y=217，浮层之外）。
- Mutation 时序（同一轮）：
  - **t=9501.3** 移除 `div[data-guif-overlay-layer="dsh-gui-frame/demo-window"]`（点下 0.4ms 后）
  - **t=9507.2** 才新增 `div[data-guif-overlay-layer="dsh-gui-frame/demo-dialog"]`
  ⇒ **摘除发生在对话层挂载之前**，所以不是「对话层把它挤掉/顶掉」，而是那次 pointerdown 的关闭动作。
- 唯一变量对照：S2（真鼠标）→ 浮窗层被摘；S5（JS `.click()`，**不发 pointerdown**）→ 两扇共存；S6（直接 API，零事件）→ 两扇共存。
- 机制出处（只读复核）：`src/client/overlay/dismiss.mjs` 的 `createDismissController.onPointerDown`——点在**浮层 React 树之外**且拦截账本为空 ⇒ `onDismiss` ⇒ `overlay/index.mjs` 里 `stack.remove(top.id)`。**相对 t32 期修复过的 F-real-6②，这条是新的正向行为**，与「宿主消失」无关。

## 4. 服务面/座位侧读数：没有 dispose、没有重装、没有注销

插桩经 `ctx` 捕获到服务面（loader 拦截见 §6 注记）：`service.__slice('overlay')` 的 **api 对象 id 恒定 = 4**，`service.__slices()` 全程 `["channel","dock","overlay","theme"]`：

- `api.dispose()` **只在 t=1190.3 被调用过一次**，那一次是**装配期的补装窗口**（平台 `slots` 晚到 ⇒ 汇合点 dispose 掉第一遍的降级件再装一次），发生在任何用户操作之前。
- S1–S7 全程（t≈8.5s–19s）：**零次 `api.dispose()`、零次切片 disposer 调用、零次切片集合变化**。
- 平台 `slots` 侧：`dsh-gui-frame/overlay` 于 t=1191 在 `shell.overlay`（order 100）注册一次后**从未注销**（`slots.disposerCalls` 只发生在 t=1191.8–1192.4 的补装/重复登记清理上）。
- ⇒ 按 R4：这一现象既不是 `raw()`（fiber 卸载），也不是「宿主被重挂」，也不是「层栈被清空」。

## 6. 旧读数为什么会长成「宿主消失」的样子（两条机制）

1. **`[data-guif-window]` 只由浮动窗渲染**（`src/client/window/floating-window.mjs`）：对话层开着时它天然为空。
   旧 RM-04a 用「窗口锚点数有没有增长」判「对话层开出来了没有」⇒ 判成「没开」⇒ **把对话层又点了一次**（t53 那轮账上是 `z=101` 与 `z=102` 两条对话层）。
2. **第④段按钮在浮层之外**，真鼠标 `pointerdown` 命中设计内的点外关闭 ⇒ **已开的浮窗被摘**（§3 的时序）。两条叠起来正好产出「窗口锚点先有后无」。
   而旧读数里的「`[data-guif-overlay-root]` 子节点 0」取自**开层之前**的那次快照（装置口径，t57 已修）——本轮 S0 的读数就是这个状态（栈长 0、无层锚点），它**不代表**开层之后宿主为空。

## 8. 没测到的 / 保留意见（不做过度结论）

- 未覆盖：多浏览器/多分辨率、HMR 热替换、真实用户长时交互、真实**触屏/拖拽**手势下的拦截账本路径（本探针只用 CDP 鼠标与键盘）。
- **一条值得产品侧确认的观察（不是缺陷断言）**：按 `dismiss.mjs` 的实现，非模态的浮动窗在**点界面其它地方**时也会被摘（始终只关最上层）。所以「先用鼠标开浮窗、再用鼠标开对话层」在真机上**必然只剩一层** —— 装置现在的 RM-04a 也是靠 `dialog(js)` 才拿到「两扇共存」。若 `docs/浮窗四证-*` 或真机留证脚本要演示「两扇共存 + 层级号递增」，需写明**第二扇用不触发 pointerdown 的方式打开**（或用 `closable:false` 的窗），否则用户照着鼠标点会看到第一扇消失。
